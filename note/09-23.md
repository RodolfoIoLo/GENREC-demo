## SASRec & Recbole?

Recbole是一个Python的推荐系统算法库,把<做一次推荐实验>中与具体模型无关的部分全部实现好了

读数据(.inter文件) → 按协议切分(leave-one-out) → 展开成序列样本 → 分批 → 训练循环 → 反向传播 → 早停 → 评测指标 → 日志落盘

它不是一个模型,是一个跑模型的框架,你只需要提供三样东西:

1. 数据文件({data_path}/{dataset}/{dataset}.inter)
2. 一个配置文件(yaml)
3. 一个模型名字(SASRec/GRU4Rec...)

> ml-1m.inter文件格式为;userID:token	itemID:token	timestamp:float

### Recbole六个组件

| 组件 | 职责 | 你本来要自己写的 |
|---|---|---|
| **Config** | 读 yaml,按 4 层优先级合并默认值 | 参数管理 |
| **Dataset** | 读 `.inter`,过滤,切分,展开序列 | 数据加载 + 切分 + 样本构造 |
| **DataLoader** | 分批,按 seed 打乱 | `torch.utils.data.DataLoader` 那套 |
| **Model** | 网络结构(SASRec / GRU4Rec / ...) | 模型定义 |
| **Trainer** | 训练循环,反向传播,早停,checkpoint | `for epoch: for batch: loss.backward()` |
| **Evaluator** | 全量排序,算 Recall/NDCG | 评测代码 |

### SASRec的具体流程

**SASRec要解决的问题**:给定用户的历史物品序列,预测下一个最有可能交互的物品

一次前向的完整流程:

| 步 | 操作 | 张量形状 / 真实数值 |
|---|---|---|
| 1 | 取用户历史 item id 序列,保留最近 200 个,**右边**补 0(左对齐) | `[200]`,内容是 `[i₁...i₅₁, 0×149]` |
| 2 | 查物品嵌入表(3417×64)+ 位置嵌入表(200×64),相加 | 两个 `[200, 64]` → 相加 → `[200, 64]` |
| 3 | 2 层因果自注意力(每层:2 头自注意力 + 前馈网络,含残差与 LayerNorm) | `[200, 64]` → `[200, 64]` |
| 4 | 取**最后一个有效位置**(下标 50,即第 51 位;不是下标 199)的向量 | `[64]` |
| 5 | 与 3417 个物品嵌入做矩阵乘 | `[3417]` 个分数 |
| 6 | 标签 = 第 52 个物品,算交叉熵 | 标量 loss |
| 7 | 反传 + Adam 更新参数 | -- |

#### 第一步:造出序列

user0在训练集里有51条交互记录,按时间排序是51个物品编号

模型需要的是一个*长度固定*的序列,所以取最近 200 个,不够的右边补 0, 最后给出[B, 200]这样的矩形张量

``` plaintext
[ i₁, i₂, i₃, ..., i₅₁, 0, 0, ..., 0 ]  # 长度 = 200
```

#### 第二步:把编号换成64个数

直接用编号,编号是整数,整数之间没有大小意义--编号2757不代表它和编号2756/2758有什么关系,模型要算的是乘法和加法,所以每个物品必须换成一串小数

怎么换?:查表!

模型里存着一张item_embedding,它有3417行,64列--正好以一行对应一个物品编号,查编号就是取第几行,得到一个64维向量,这个向量就是物品的表示,此时我们就可以得到一个200×64的张量

同时,位置也需要编号!

注意力机制本身分不清第1个和第51个,把序列打乱,算出来的结果是一样的,所以要另外给每个位置配64个数(另一张表position_embedding,200行,64列),这时候我们只需要将得到的200×64的物品嵌入张量和200×64的位置嵌入张量相加,就得到了最终的输入张量

#### 第三步:让每个位置看到前面的位置

现在每个位置有 64 个数,但这 64 个数只知道它自己是什么物品,完全不知道前面发生过什么.要预测下一个物品,就必须把前面 51 个位置的信息汇总起来.

*自注意力做的事*:对某个位置,拿它的 64 个数去和前面每一个位置的 64 个数算一个"相关度"分数,然后按分数把前面那些位置的 64 个数加权求和,得到这个位置新的 64 个数.

**只往前看,不往后看**

为什么不能往后看:位置 10 的答案,就是位置 11 那个物品.如果位置 10 能看到位置 11,等于直接把答案抄进输入,模型学不到东西.

怎么实现"不能往后看":算出相关度分数之后,把"不许看"的那些位置的分数改成一个极大的负数(-10000).这些分数接下来要过 softmax(把分数变成加起来等于 1 的权重),而 -10000 过完 softmax 之后权重几乎是 0.

循环2次,这就是"大白话版"的2层因果自注意力.

#### 第四步:只取一个位置的64个数

现在我们手上拥有的依然是一个200×64的张量,需要做的是*一个能代表用户兴趣的向量*,用来预测下一个物品!

那么取那哪个位置呢?聪明的你很快发现,第51个向量,也就是用户最后一个真实行为所在的位置,因为它看过前面全部50个位置,所以它身上带着整段历史的信息!

#### 第五步:和全部物品逐个比一遍

我们现在已经拿到了代表用户兴趣的一个64维向量,这时我们想起来有一张表item_embedding,表中每个物品各自有64个数,把我们得到的向量和表中的3417个向量做点积,得到3417个分数,分数越高,模型就越认为这和物品是下一个用户会看的

#### 第六步:算loss

正确答案是user0交互的第52个物品,通过把3417个分数变成3417个概率(加起来等于1),然后看正确答案被分到了多少概率,分得越少,loss越大.

这一步可以看成是:看模型给正确答案分配了多少信心

从分数到概率的算法是softmax:每个分数取指数exp,再除以所有指数的和

loss的计算公式:loss = -ln(正确答案的概率)

ln是自然对数,输入越接近1,输出越接近0,输入越接近0,输出越大

#### 第七步:调参数

按这个数,反过来算出<表里哪些数该往哪个方向改,该多少>,然后改一遍,这就是训练的一步

如此循环,就是训练

> 一些说明:
>
> 1. item_embedding和position_embedding是模型自带的参数,训练刚开始时,这些数是随机填充的,,每走一个batch,第七步就会对它们进行一些改动
>
> 2. SASRec有哪些可调的参数?
>
> 参数在这里可以分为两类:
>
> 一种是训练过程自己改动的,就叫做参数,比如item_embedding和position_embedding,它们的数值会随着训练不断改变,它们分别有64×3417和64×200参数,根据训练日志的值参数共计331584个
>
> 还有一种是超参数,是写在yaml中的,有n_layers,n_heads,hidden_size,inner_size,dropout,loss_type等合计十余个
>
> 3. batch?epoch?seed?
>
> batch:一次前向同时处理样本个数
>
> epoch:把整个训练集完整过一遍
>
> seed:随机数生成器的起始值,确定初始的331584个参数,以及每个epoch中batch的顺序等
>
> 以我的训练为例:
>
> 一共999611 - 6040 - 6040 - 6040 = 981491个样本,每个epoch内,480个batch依次覆盖981941条,不重不漏,整个训练进行了43个epoch(早停)
