# 09-17 记录

## 首先 -- 关于实验协议

- 数据集: MovieLens ml-1m
- 反馈类型: 隐式(有交互=正样本)
- k-core: 5-core
- 划分协议:leave-one-out
- 评价协议:全量排序
- 指标 Recall@5/10 NDCG@5/10
- 随机种子:42(全局统一)
- ID编号:过滤后重映射为0...N - 1

## 数据预处理

movies.dat原本样式:
```
movieId::title::genres
```

users.dat原本样式:
```
userId::gender::age::occupation::zip_code
```

ratings.dat原本样式:
```
userId::movieId::rating::timestamp
```

需要想清楚自己的任务:根据一个用户的观看历史,通过生成式推荐向用户推荐下一个电影

### 具体步骤

1. 读取原始数据(dat文件)
2. 丢掉评分列(隐式反馈)
3. 迭代5-core(过滤掉交互次数小于5的用户和物品)
4. 重映射ID(过滤后重映射为0...N - 1)
5. 排序+划分(用户的历史按时间戳升序排序,最后一个交互作为测试集,倒数第二个交互作为验证集,其余作为训练集,leave-one-out)
6. 生成文件

> 关于生成的文件
> - train.jsonl
> - valid.jsonl
> - test.jsonl
> 
> 以上这三个文件的形式都是一用户一json,每个json都包含的两个字段:user_id & history,valid.jsonl和test.jsonl中还包含一个字段:target,表示用户的下一个电影
> 
> - item_text.json:重映射后的电影ID&电影名称和电影种类的映射
> 这个文件的作用是作为文本编码器的输入,文本编码器编码出的向量进入RQ-VAE
>
> - ml-1m.inter:内容为按照userID -> timestamp排序的交互历史,作用是
 
## 数据统计-验证研究的价值 

### 为什么要统计 & 统计什么

统计项目 | 说明
| --- | --- |
用户数/物品数/交互数 | 基础
物品热度分布(长尾) |  ⭐ 核心论证:冷门物品样本少 → one-hot ID embedding 学不好 → 这就是用语义标识符的动机
用户活跃度分布 | 说明任务难度,活跃用户系列长,模型更容易
稀疏度 | 说明推荐任务本质是极度稀疏的矩阵补全
时间跨度 | 判断时间是否有时间的明显漂移

### 产出三张图片

1. item_freq_loglog.png: 长尾图

    - x 轴 = 物品按热度排名(对数),y 轴 = 该物品的交互次数(对数)
    - 理想的长尾(幂律分布)在这张图上是一条直线;曲线越平,拖得越长,说明长尾越重
    - 这张图就是"为什么需要语义标识符"的视觉证据
2.  item_freq_hist.png: 频次直方图

    - x 轴 = 交互次数,y 轴 = 有多少物品落在这个频次(对数)
    - 你会看到一个集中在低频端的尖峰:绝大多数物品只有个位数到几十次交互
    - 对比一下最热物品的交互数(item_freq_max),差距越悬殊,论证越有力
3. seq-len_hsit.png: 序列长度分布

    - x 轴 = 用户交互数,y 轴 = 用户数
    - 用途:决定模型的 max_seq_len 超参.别取最大值(会被极端值拖爆显存),看 P90 或 P95 更合理
