## 复习一下ssh()

首先看我的电脑上`~/.ssh`目录下的文件
- `config` —— 别名配置。写了 `Host amax510` 之后,`ssh amax510` 就等于后面那一串完整参数
- `id_ed25519` —— **私钥**。绝不给任何人,整个认证的安全就靠它不外泄
- `id_ed25519.pub` —— 对应的**公钥**。这串是可以公开的,传到服务器的 `authorized_keys` 里
- `id_rsa`' —— 老的 RSA 私钥(历史遗留,现在推荐 ed25519)
- `id_rsa.pub`
- `known_hosts` —— 记录连过的服务器的主机公钥指纹。连过的服务器不用再确认
- `known_hosts.old` —— `known_hosts` 的备份,ssh 改动它之前会先存一份

> `.pub` 是公钥、不带后缀的是私钥,就这一个区别。**看到谁要你的 `id_ed25519`(不带 .pub),那是要偷钥匙。**

ssh就是在客户端和服务器之间建立的加密通道

### 连接步骤:

1. **TCP 三次握手** —— 先跟服务器的 22 端口建立一条能用的 TCP 连接
2. **版本协商 + 密钥交换** —— 双方报版本号,然后用 DH 算法各自算出一个**相同的对称密钥**(交换过程是公开的,但别人算不出这个结果)。之后的通信都用它加密
3. **服务器签名,客户端验签** —— 服务器拿它的主机私钥签一段数据,客户端用公钥验。第一次连的时候会弹
   `The authenticity of host ... can't be established`,让你确认的那串指纹就是这一步。验过了写进 `known_hosts`,下次不再问。
   **这一步防的是中间人**(别人冒充服务器),和下一节的登录认证是两件事
4. **用户认证** —— 两种方式:
   - 密码认证:密码在加密通道里发过去,服务器比对
   - **公钥认证**:客户端用 `id_ed25519`(私钥)签一段数据,服务器拿 `authorized_keys` 里的公钥验签。**私钥全程不出本机**

我们配的是第 4 步里的公钥认证,所以叫"免密登录"—— 不是不认证,是**不用输密码**了。第 3 步该确认的指纹还是得确认。

> 顺带:第 2 步之后,整条链路上**只跑密文**。所以在服务器上 `tcpdump` 抓包,抓到的 SSH 流量是看不出来内容的。

### 命令:

生成密钥:
```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```

把公钥传到服务器:
```bash
cat ~/.ssh/id_ed25519.pub | ssh zby@100.100.97.78 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

本地配置`~/.ssh/config`:
```
Host amax510
    HostName 100.100.97.78
    User zby
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60
```

### 传统VPN vs tailscale/netbird

| | 传统VPN | tailscale/netbird |
|---|---|---|
|拓扑|星型,所有流量绕中心网关|Mesh,节点两两直连|
|瓶颈|中心带宽、单点故障|无中心瓶颈|
|延迟|翻倍(去+回都要过中心)|直连时≈物理延迟|
|打不通时|——|降级走中继(DERP / TURN)|

### 三层架构

```
┌─────────────────────────────────────────────
│ 控制平面 Control Plane                       
│ 认证身份 · 分发密钥 · 交换地址 · 下发 ACL     
│           ↓ 下发网络地图(netmap)             
├─────────────────────────────────────────────
│ 数据平面 Data Plane                          
│ WireGuard 隧道 · 端到端加密 · 点对点直传       
│           ↓ 打洞失败时降级                    
├─────────────────────────────────────────────
│ 中继平面 Relay                               
│ DERP / TURN · 转发密文,解不开内容             
└─────────────────────────────────────────────

```

**控制平台挂了,已建立的连接照跑不误**, 服务器只负责"认人,发钥匙,指路",之后连你的数据包都看不到!

### conda VS venv

venv只隔离Python包,conda连Python解释器本身都隔离

| | venv / virtualenv | conda env |
|---|---|---|
|是谁 |	Python 标准库自带 | 独立的包管理器（Anaconda / Miniconda） |
|隔离范围|只有 Python 包|	包 + Python 解释器 + 非 Python 二进制依赖|
|能换 Python 版本|❌ 不能|✅ conda create -n x python=3.9 直接给|
|包来源|PyPI（pip）|	conda 频道（defaults / conda-forge），环境内也可用 pip|
|依赖解析|只管 Python 层面|	SAT 求解器，跨语言跨二进制|
|体积 / 速度|小、快|	大（几百 MB 起）、慢|
