## tmux

[想看更详细的讲述?](https://www.ruanyifeng.com/blog/2019/10/tmux.html)

> 传统的会话与进程:
> 命令行的典型使用方式是,打开一个终端窗口(terminal window),输入命令,这样用户与计算机临时的交互,成为一次会话(ssession)
> 会话的一个重要特点是,窗口与其启动的进程是连在一起的,打开窗口,绘画开始,关闭窗口,会话结束,回话内部的进程也会随之终止
> 为了解决这个问题,可以将会话与窗口"解绑"!

所以tmux怎么用的呢?

首先,完整的工作空间依然是Session

``` bash

tmux new -s session_name # 新建一个会话
tmux attach -t session_name # 连接到一个会话

```

### 核心机制:为什么它能救命

Session 里面还能再分层:

```
Session(会话)
 └─ Window(窗口)      ← 一个窗口占满整个终端屏幕
     └─ Pane(面板)    ← 一个窗口切成几块,每块跑一个程序
```

真正关键的一点:**Session 是挂在 tmux 的服务进程(`tmux server`)下面的,不是挂在你的 SSH 连接上的。**

平时不开 tmux 时,你的 bash 是 SSH 会话的子进程。SSH 一断,内核发 `SIGHUP`(hang up)给这个会话里的**所有**进程,你正在跑的 `train.py` 就跟着死了。

开了 tmux 之后,父进程变成 tmux server。SSH 断掉只是**你和 tmux 之间那条线断了**,tmux server 和里面的进程一点没受影响 —— 这就是"解绑"。

### 必背三件套

```bash
tmux new -s train       # 新建名为 train 的会话
tmux ls                 # 列出所有会话
tmux attach -t train    # 回到这个会话(断线重连后就用这条)
```

**脱离会话**:按 `Ctrl+B`,松开,再按 `D`(detach)。
注意是"脱离"不是"关闭"—— 脱离之后里面的东西照跑。

**彻底关闭**:在里面敲 `exit`,或者 `tmux kill-session -t train`。

### 快捷键都按 Ctrl+B 开头

| 按键 | 作用 |
|---|---|
| `Ctrl+B` 然后 `D` | 脱离当前会话(detach) |
| `Ctrl+B` 然后 `C` | 新建一个窗口(create) |
| `Ctrl+B` 然后 `N` / `P` | 切到下一个 / 上一个窗口 |
| `Ctrl+B` 然后 `%` | 把当前窗口**左右**切成两个 pane |
| `Ctrl+B` 然后 `"` | 把当前窗口**上下**切成两个 pane |
| `Ctrl+B` 然后方向键 | 在 pane 之间跳 |
| `Ctrl+B` 然后 `[` | 进入滚动模式,用方向键 / PageUp 往上翻历史输出 |

> 最后一条特别有用:tmux 里鼠标滚轮默认不管用,翻历史得按 `Ctrl+B` `[`。

### 我们的规矩

**凡是超过几分钟的任务,一律先 `tmux`。**

尤其是训练(第 2 周跑 SASRec、第 5-6 周训 T5),训练到一半笔记本断网、电脑休眠、Tailscale 重连 —— 这些都会杀掉前台进程。用 tmux 就没有这个问题。

## 生成式模型到生成式推荐

### 判别式模型 & 生成式模型

判别式模型学的是"怎么分类",生成式模型学的是"数据本身长什么样子"

- 判别式模型:一只狗的照片(像素向量x) -> 判别函数(神经网络/SVM) -> 一个标签(狗99%)
- 生成式模型:随机噪声z(比如512个数) -> 生成器(神经网络) -> 一只新的狗(现实中不存在)

- 判别式模型学的是条件概率 p(y∣x) -------- 给定输入 x,标签 y 的分布.它只关心"分界线在哪",不关心猫本身长什么样.
- 生成式模型学的是数据本身的分布 p(x)(或者联合分布 p(x,y))-------- 它要回答的是"一张猫图出现的可能性有多大".

有意思的是,如果你有了 p(x,y),用贝叶斯公式就能反推出 p(y∣x),所以生成式在理论上更强大.代价是它难得多.
